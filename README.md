# NVENC プラグイン出力

YMM4(ゆっくりMovieMaker4)での動画書き出しを高速化するためのプラグインです。  
NVENCのパイプライン化により非同期でのエンコードを行い、GPUを効率的に使えるようにしています。

> **重要: 動作に必要な YMM4 の最低バージョンが変わりました。**
> 本バージョンから `IVideoFileWriter3` を実装するため、`IVideoFileWriter3` を持つ YMM4 が必要です。
> それ以前の YMM4 では、「GPU直渡し」をOFFにしていてもプラグインを読み込めません。古い YMM4 を使う場合は更新前のバージョンをご利用ください。

## このフォークについて

これは [tarutaru247/YMM4_NVEncPlugin](https://github.com/tarutaru247/YMM4_NVEncPlugin)（v1.0, `c7cf161`）のフォークです。ライセンスは **MIT** で、上流の著作権表示を維持しています（[LICENSE](LICENSE)）。

**Radeon (AMF) 版からの継承を含みます。** [disnana/YMM4_AMF_Plugin](https://github.com/disnana/YMM4_AMF_Plugin)（tp-li-dev / Disnana、MIT。こちら自体が上流の NVEnc プラグインから派生）で行われた次の改良のうち、ベンダーに依存しない部分や設計を、NVENC 向けに取り込んでいます。

- 所有テクスチャのスロットプールと、専用の出力回収スレッド（AMF 版の設計を NVENC の API に合わせて書き直したもの）
- MP4 の音声トラック長（tkhd）の修正、最初のエラーを保持する処理、入力検証、完了フレーム数の照合
- プロファイリング JSON と「映像・音声を破棄」モード（`ExportProfiler` / `NvencProfiling.h` は AMF 版の `ExportProfiler` / `AmfProfiling.h` を翻案）
- 出力検証スクリプト（`scripts/Validate-Output.ps1` と `scripts/Mp4Timing.Common.ps1`、`tests/Test-Mp4Timing.ps1` は AMF 版を翻案）
- GPU 直渡し（`IVideoFileWriter3`）のオプション

参照した AMF 版のコミットは `fb0da45`（v0.2.2）です。出典と各部品の扱いは [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt) にあります。

このフォーク独自の変更には、AV1 のシーケンスヘッダ解析の修正、D3D11 マルチスレッド保護の有効化（出力スレッドとのデッドロック対策）、WSL2 から実 GPU で動かすネイティブのスモークテスト（`tests/native-smoke/`）があります。

> **このフォークは未リリースです。** 下の「インストール」のリリースは上流のものです。動作確認は、RTX 4080 上の合成フレームによるネイティブ層のテストと、YMM4 4.56.1.0 Lite での 1080p60 H.264 出力までです。HEVC / AV1 の実プロジェクト出力、長時間運用、複数 GPU は未確認です。

## インストール
1. [リリースページ](https://github.com/tarutaru247/YMM4_NVEncPlugin/releases)もしくは[Booth](https://tarutaru247.booth.pm/)から、NVEncPlugin.ymmeをダウンロード
2. ダウンロードしたファイルを開くと、自動的にYMM4のプラグインインストーラーが起動します
3. インストーラーの指示に従いインストール

## アップデート
1. YMM4を終了します
2. 最新版の `NVEncPlugin.ymme` をダウンロードします
3. ダウンロードした `.ymme` ファイルを開き、YMM4のプラグインインストーラーで上書きインストールします
4. YMM4を起動し、出力形式に「NVENC プラグイン出力」が表示されることを確認します

うまく更新されない場合は、YMM4のプラグインフォルダから古い `NVEncVideoWriterPlugin` を削除してから、再度 `.ymme` を開いてインストールしてください。

## 使い方
1. YMM4の出力形式から「NVENC プラグイン出力」を選択
2. コーデック（H.264 / H.265 / AV1）、出力品質、ビットレート方式を設定
3. H.265 の場合は「安定性重視（遅い）」で同期エンコードに切り替え可能（デフォルトは非同期）
4. 「GPU直渡し（実験・IVideoFileWriter3）」は既定でOFFです（下記「GPU直渡し」参照）
5. デバッグログが必要な場合は「デバッグログを書き出す」を有効化
6. 出力形式は`.mp4`

## GPUの選択について
このプラグインは、YMM4本体が使用するGPUをそのまま利用します。  
そのため、YMM4が内蔵GPUなど、NVIDIA以外のGPUで動作している場合このプラグインは正常に動作しません。

以下のようなエラーが出る場合は、YMM4が内蔵GPU側で動作している可能性が高いです。  
- `nvEncOpenEncodeSessionEx failed (1)`  

Windowsの「グラフィック設定」で `YukkuriMovieMaker.exe` を  
**高パフォーマンスGPU（NVIDIA）に固定**してから、再度お試しください。  
手順は公式FAQをご参照ください。  
公式FAQ: https://manjubox.net/ymm4/faq/startup_trouble/select_gpu/


## 必要環境
- Windows 11
- NVIDIA GPU と最新ドライバ
- `IVideoFileWriter3` を持つ YMM4（.NET 10 対応版）。古い YMM4 ではGPU直渡しがOFFでもプラグインを読み込めません

AMD GPUやIntel GPUでは動作しません

AV1 出力を利用するには、AV1 の NVENC エンコードに対応した NVIDIA GPU が必要です。

## GPU直渡し（実験・IVideoFileWriter3）
- 設定の「GPU直渡し（実験・IVideoFileWriter3）」は既定でOFFのオプションです。ONにすると、YMM4 は CPU 読み取り用ビットマップへの中間コピーを省き、描画済みの GPU フレームを直接渡します
- プラグイン側の入力テクスチャプールへの GPU コピーは維持します（完全なゼロコピーではありません）
- 速度向上は保証しておらず、効果は未検証です。設定は次に開始する出力から適用され、1回の出力中は固定です

## 音声
- AAC固定（Media FoundationのAACエンコーダを使用）

## 入力テクスチャプールとスレッド構成
- 設定の「入力テクスチャプール」（4 / 6 / 8、標準 6）で、NVENC に渡す入力テクスチャの枚数を選べます。大きいほど GPU メモリを多く消費します
- 各スロットは専用の入力テクスチャ・ビットストリームバッファ・完了イベントを持ち、エンコード中のテクスチャを次フレームが上書きしないようになっています
- フレームのコピーと入力リソースの Map/Unmap は書き出し（レンダー）スレッドのみで行い、ビットストリームの回収と MP4 への書き込みは専用の出力スレッドが行います（音声と映像の MP4 書き込みは排他制御されます）
- 非同期を使わない設定（H.265 安定性重視など）では、同じプールを使いつつレンダースレッド上で同期的に回収します

## デバッグログ
- デフォルトでは出力されません
- 「デバッグログを書き出す」を有効にすると、出力ファイルと同じ場所に `.nvenc_log.txt` が生成されます

## 診断オプション

設定画面に、性能調査用の2つのチェックボックスがあります（どちらも既定オフ）。

- 「プロファイリング結果を書き出す（集計JSON）」: 終了時に `出力名.nvenc_profile.json` へ区間別の時間集計を保存します。
- 「計測専用：映像・音声を破棄（MP4を作成しない）」: 映像・音声を破棄し、MP4を作成しません。必ず新しい出力名で使ってください。

通常の出力では使用しないでください。詳細は [docs/profiling.md](docs/profiling.md) を参照してください。

## 配布用パッケージ
プラグインフォルダをzipで圧縮し、拡張子を`.ymme`に変更するとワンクリックインストールが可能です。
